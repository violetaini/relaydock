# 更新日志

## v0.6.17 (2026-08-30)

### 本次更新
- 用户服务授权统一为“套餐授权”与“自定义授权”两种互斥模式。管理员可以一次配置固定节点、服务器和中转授权，也可以批量切换用户授权来源；套餐中的节点、服务器和中转资源会携带来源信息，并在套餐修改、切换、到期或解绑后自动对账和回收。
- 套餐与自定义授权现在共用同一套有效权限、计费和页面可见性判定。用户只能看到当前实际获权的节点、订阅和中转服务，原有全局 API 权限仍然保留；Classic Shadowsocks 也可作为受管固定节点安全分配。
- 获得服务器授权的用户可以在允许的协议、传输和安全配置范围内创建自己的专属节点。创建过程会校验服务器、端口、证书和 Reality 目标，先安装拒绝策略再写远端，失败时回滚；授权撤销后会清理专属入站和凭据。
- 受管 WireGuard 入站改为给每位用户分配独立 Peer、地址和加密保存的私钥，并在发布订阅前等待 Agent 与限流策略确认。用户禁用、到期、超额、套餐切换或删除时均先撤销远端访问，失败会保留待重试状态而不是放行；导入的 WireGuard 节点继续使用其原有身份。
- 套餐额度改为按资源配置。固定节点支持独立流量、限速和设备额度及用户级覆盖，中转支持每条转发限速，服务器授权继续支持节点数量、连接数和流量额度；固定节点流量可按自然月、自然季度或自然年重置。
- 加固授权切换、节点删除、用户禁用和私有路由撤销的并发与回滚。远端删除、限流更新或 Agent 确认失败时会保持可恢复的 pending 状态，后台对账只处理当前代际，避免旧任务恢复已经撤销的访问。
- 修复 WireGuard 节点在部分网络中无法测速的问题。Mihomo 探测流量使用独立本地 UDP 中继并映射到固定公网源端口；防火墙规则只绑定该本地中继和已建立回包，不再绑定某个远端 IP/端口，因此新增服务器、端口变化和 DNS 轮换无需维护端点清单。

### 影响与兼容性
- 启动迁移会新增授权来源、直接节点授权、用户专属节点、WireGuard 身份及资源额度相关字段和表，并按现有 `package_id` 回填用户授权模式。已有套餐用户保持套餐模式，其他普通用户进入自定义模式；不属于当前模式的旧授权会转为待清理状态。
- 旧版套餐“总流量、总限速、自动限速”及对应用户级聚合覆盖会在迁移中清零，避免继续与资源明细重复执行。升级前请确认需要保留的额度已配置到固定节点、服务器授权或中转授权；设备额度和已有按节点配置不受此项清理影响。
- WireGuard 独立 Peer、固定节点拒绝策略和中转限速依赖新版 Agent 的 `wireguard_peer_users_v1`、`limiter_denied_v1` 与 `forwarding_speed_limit_v1` 能力。旧 Agent 不满足能力时，相关写操作会在落库或远端变更前拒绝；请先升级并等待服务器重新连接。
- 用户自助创建专属节点只适用于使用内置 Xray 且 Agent 在线的服务器。外部 Xray 仍由管理员安装、升级和管理，不会被本版本自动替换，也不会开放给用户自助创建节点。
- 裸机 / systemd 部署会安装 WireGuard 探测中继的防火墙脚本、配置和 systemd 依赖。手工维护旧四字段或五字段端点配置的实例应先移除旧状态，再改用“本机 IPv4、中继端口、公网源端口”三字段配置；脚本仍可识别旧状态并安全清理对应规则。
- Docker 容器不能代替宿主机持久配置 iptables。Docker 部署若需要受限网络下的 WireGuard 测速，需在宿主机配置等效的 UDP SNAT 与已建立回包规则；普通节点测速和导入 WireGuard 配置不受数据迁移影响。

## 更新版本
- 裸机 / systemd：使用 `v0.6.17` Release 中的 `install.sh update` 完整更新。此流程会同时安装 WireGuard 探测中继脚本、配置和 systemd unit；仅使用面板内置更新不会补装这些宿主机资产。完成后再逐台升级并确认 Agent 已重连。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`；WireGuard 探测中继的宿主机防火墙规则需单独维护。

## 操作方法
1. 更新前保留可恢复的数据库备份，并导出现有套餐、用户授权和资源额度配置；确认服务器可以访问 GitHub Release 下载域名。
2. 检查旧套餐中的总流量、总限速和自动限速，把仍需执行的限制迁移到固定节点、服务器授权或中转授权的资源明细。
3. 裸机 / systemd 部署执行 `install.sh update`，等待宿主机资产安装、数据库迁移、后端健康检查和网页版本检查完成；随后逐台升级 Agent，并确认能力与在线状态已经刷新。
4. 打开用户服务授权，核对每位用户的套餐或自定义模式、固定节点、服务器和中转来源；重点确认套餐切换、到期和已删除资源没有遗留访问。
5. 在至少两个不同远端服务器上执行 WireGuard 延迟测试，并检查 `arcway-wireguard-probe-egress.service` 为 active、测试结果不再因端点不在静态清单而失败。
6. Docker 部署在宿主机拉取并重建镜像；需要 WireGuard 固定源端口探测时，再由宿主机管理员应用等效防火墙配置。
