# 更新日志

## v0.6.8 (2026-08-02)

### 本次更新
- Agent 节点安装改为只从与控制端版本完全一致的 GitHub Release 下载二进制。
- 节点安装脚本会先读取同一 Release 的 `checksums.txt`，严格校验当前架构的 Agent 文件，再继续安装；GitHub 下载或校验失败会直接停止，不再回退到面板下载。
- 面板不再托管 Agent 二进制，也不再把 `Agent 安装资产` 列为一键更新组件；更新页仅保留控制端、网页、守卫和测速资产。
- GitHub Release 继续保留 AMD64 与 ARM64 Agent 二进制、校验和及源码溯源校验，供节点安装脚本直接使用。

### 影响与兼容性
- 新增或重装受管节点时，目标服务器必须能够访问 GitHub Release；面板地址不再是 Agent 二进制的备用下载源。
- 已接入的 Agent、节点配置、数据库和订阅数据不受影响。
- 裸机面板升级会移除 systemd unit 中旧的 `ARCWAY_AGENT_ASSET_DIR` 项，但会保留历史 Agent 缓存目录和操作员维护的 `EnvironmentFile`，以便回滚或自行清理。
- Docker 镜像不再包含 Agent 本地副本；Docker 更新方式仍是在宿主机拉取并重建镜像。

## 更新版本
- 裸机 / systemd：在面板“系统设置 → 系统更新”检查 `v0.6.8` 后确认更新。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`。

## 操作方法
1. 裸机 / systemd 部署在面板完成完整更新，等待产品事务显示完成。
2. 后续创建或重装节点时，确认目标服务器能够访问 `github.com` 及 GitHub Release 下载域名。
3. Docker 部署在宿主机拉取并重建镜像，不要在容器内点击原地更新。

## 验证
- 发布前已通过 Docker Go 1.26 `go test ./...`、Agent 安装脚本定向测试、安装事务测试、发布包契约测试、发布事务预检、发布说明契约测试和相关脚本语法检查。
- GitHub Release 资产校验与生产面板完整更新将在标签发布后继续验证。
