# 更新日志

## v0.6.16 (2026-08-10)

### 本次更新
- 新增完整的 Proxy Provider 管理与订阅交付流程。用户可以基于自己有权访问的外部订阅创建、编辑、轮换和删除 Provider，并配置节点过滤与 Mihomo 健康检查；Mihomo 客户端可使用原生 Provider，其他客户端由服务端安全展开节点。
- Provider 访问凭据改为服务端生成、加密保存且仅存储哈希用于校验，并绑定所有者、来源状态和账号状态。用户改名、凭据轮换、Provider 删除或停用来源后，旧访问能力会按预期失效。
- 加固共享订阅与模板渲染。跨用户分配、原始 YAML、模板、覆盖脚本和强制外部同步的最终输出都会检查 Provider 能力，避免撤销订阅分配后仍可复用其他用户的持久凭据。
- 外部订阅同步现在按调用者可访问的文件计算使用范围，并对 Provider 来源、缓存键及直连 URL 做租户隔离；订阅 URL、响应内容、模板变量和上游凭据不再写入日志。
- 内置 Telegram Bot 与 Mini App，增加管理员设置、公告、用户注册、订阅和通知流程，并限制机器人访问范围与管理操作权限。
- Xray 路由改为基于远端最新配置串行执行、带版本校验和失败回滚的原子热更新，移除旧隧道管理入口，并强化跨服务器路由与转发租约。
- 加固登录会话、TOTP、暴力破解限制、证书 DNS 凭据、备份恢复、用户删除及多租户资源授权；安全升级会撤销不再满足新约束的历史会话。

### 影响与兼容性
- 启动迁移会为 Proxy Provider 补充加密凭据字段、所有者名称唯一约束及相关索引；现有外部订阅和普通订阅文件不需要手工迁移。
- 共享给其他用户的订阅若包含 Provider 定义，会按请求用户和客户端能力进行服务端物化或拒绝不安全的原始能力；移除用户分配后，已复制的跨所有者 Provider 凭据不能继续访问。
- 旧 `/api/admin/tunnels` 与 `/api/admin/tunnel-chains` 管理接口已经退役；没有数据库主记录的历史转发资源不会自动导入，请在升级前后由管理员盘点并清理。
- 本次安全升级会撤销旧版本签发的登录会话，升级后所有用户需要重新登录一次；密码修改、账号禁用或删除也会立即撤销已有会话。
- 使用 `?token=` 调用通用认证 API 的第三方程序必须改用 `Authorization: Bearer <token>`；面板 WebSocket 已自动改用短期一次性票据。
- 原生 Proxy Provider 要求系统 `master_url` 为可公开访问的绝对 HTTPS 地址，仅真实回环地址允许 HTTP。
- Telegram 默认关闭；启用前需配置 Bot Token、公开 `master_url` 和 Telegram 管理员 ID。
- 外部 Xray 仍由用户安装和管理；本版本不会替换用户管理的 Xray 内核。Mihomo、规则与 geodata 的既有更新策略不变。
- Docker 部署仍需在宿主机更新镜像，不能在容器内执行面板原地更新。

## 更新版本
- 裸机 / systemd：在面板“系统设置 -> 系统更新”检查并更新到 `v0.6.16`。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`。

## 操作方法
1. 更新前保留可恢复的数据库备份，并确认服务器可以访问 GitHub Release 下载域名。
2. 裸机 / systemd 部署在面板执行完整更新，等待后端健康检查和网页版本检查完成，然后重新登录。
3. 更新后打开 Provider 管理，确认 `master_url`、外部订阅来源、处理模式和健康检查配置正确；需要吊销旧客户端访问时执行凭据轮换。
4. 检查已分配给其他用户的订阅，确认 Mihomo 原生 Provider 与其他客户端的服务端展开结果符合预期。
5. 使用 Telegram 时，在系统设置中配置 Bot Token、管理员 ID 并启用功能，再验证邀请注册、账号绑定和 Mini App。
6. Docker 部署在宿主机拉取并重建镜像，不要在容器内点击原地更新。
