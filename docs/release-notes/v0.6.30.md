# 更新日志

## v0.6.30 (2026-11-28)

### 本次更新
- 修复系统在线更新服务单元自动识别问题：当部署环境使用 `relaydock.service` 且未显式配置 `ARCWAY_SYSTEMD_UNIT` 环境变量时（例如 `arcway.service` 被屏蔽或已迁移至 `relaydock.service`），更新事务不再固定回落至 `arcway`，而是自动通过进程 cgroup（`/proc/self/cgroup`）与系统服务单元目录识别当前真实运行的 systemd 服务单元。
- 安装脚本增强：新增并写入 `Environment="ARCWAY_SYSTEMD_UNIT=$SERVICE_NAME"` 配置，确保持久化更新链路一致性。
- 嵌入式前端快照与版本契约同步升级至 v0.6.30。

### 影响与兼容性
- 控制端主程序与前端控制台版本统一升级至 v0.6.30，API Contract 保持为 3。
- 兼容现有 `arcway.service` 与 `relaydock.service` 两种服务命名规范，已部署服务无需手动迁移即可安全执行后续在线更新。

## 更新版本
- 裸机与 systemd 服务：使用面板内置在线更新或运行更新脚本升至 v0.6.30，数据目录及现有配置自动保留。
- Docker 容器部署：拉取并使用 ghcr.io/violetaini/relaydock:0.6.30，映射既有数据卷即可。
- 独立前端部署：采用配套 release bundle 中的 relaydock-web.tar.gz 替换 Web 静态资源。

## 操作方法
1. 若此前因服务单元名称不匹配导致面板提示 `recovery_required`，修复当前服務单元或清理中断事务状态后即可正常通过面板「立即更新」升级到 v0.6.30。
2. 升级完成后，后续版本将自动识别正确的 systemd 单元完成停机、替换、启动与健康检查闭环。
