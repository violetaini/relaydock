# 更新日志

## v0.6.11 (2026-08-04)

### 本次更新
- 外置 Xray 的生命周期现在完全由管理员控制：Agent 启动、Agent 自更新、节点授权变化、到期停用和自动证书同步均不会停止、启动或重启整套外置 Xray。
- 节点失去授权时，Agent 仅通过 Xray 的运行时接口撤下 Arcway 自己管理的入站；恢复授权时也只热加入这些入站。已由管理员手动停止的 Xray 会保持停止状态。
- 自动证书续期和内容同步只写入证书文件，不再重启 Xray；新证书会在管理员下一次明确重启或重载 Xray 时生效。
- 新建的面板托管 Reality 入站会写入 `minClientVer: "1.0.0"`，改善 Clash Meta 的连接兼容性。服务器 Xray 配置页新增“修复兼容性”，可无整机重启地补齐旧的面板托管 Reality 入站；受影响的单个入站会短暂重连。
- 正式发布包已固定本次 Agent 生命周期修复和新的控制台界面，面板更新会从同一 GitHub Release 校验下载。

### 影响与兼容性
- 本次只改变 Arcway 管理的入站和自动化流程，不接管、安装、替换或自动启动管理员自管的外置 Xray。
- 如果外置 Xray 本来就是停止状态，授权和配置同步会等待管理员自行启动 Xray；不会为了同步而拉起服务。
- 旧版面板托管 Reality 入站可在“服务管理”的 Xray 配置页执行一次“修复兼容性”。手工维护或非 Arcway 当前接管范围内的入站不会被修改。
- Docker 部署仍需在宿主机更新镜像，不能在容器内执行面板原地更新。

## 更新版本
- 裸机 / systemd：在面板“系统设置 -> 系统更新”检查并更新到 `v0.6.11`。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`。
- 受管节点：控制端更新后，Agent 会按发布包校验更新；外置 Xray 本身仍由管理员在面板中明确管理。

## 操作方法
1. 更新前完成可恢复的加密备份，并确认服务器可以访问 GitHub Release 下载域名。
2. 裸机 / systemd 部署在面板执行完整更新，等待事务、后端健康检查和网页版本检查全部完成。
3. 对已有的面板托管 Reality 入站，打开目标服务器的 Xray 配置页，确认影响范围后执行“修复兼容性”。
4. Docker 部署在宿主机拉取并重建镜像，不要在容器内点击原地更新。
