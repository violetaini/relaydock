# 更新日志

## v0.6.13 (2026-08-05)

### 本次更新
- Xray 入站改为只以面板数据库中的服务器节点为准：从“节点管理”创建或修改代理节点，后端会把完整入站配置热同步到对应 Agent；Agent 或配置文件中额外出现、但数据库没有对应节点的“幽灵入站”会被自动移除。
- 服务器服务管理窗口不再提供容易与节点管理混淆的“入站”页签。VLESS、WireGuard 等服务器代理节点统一从“节点管理”创建；导入的外部节点只用于生成订阅、连通性测试和分配给用户，不会反向写入服务器 Xray。
- 升级时会安全接管已有数据库节点对应的入站，并保留有效配置；历史自动扫描记录、外部手工入站和无法确认归属的运行时入站不会被误认作面板节点。
- 入站用户会根据数据库中的当前用户、授权、套餐和流量状态重新生成，Agent 侧临时添加的用户不会反向进入数据库。
- 常规新增、修改、删除、节点停用、授权变化和证书同步继续采用热更新，不会为入站对账重启 Xray。只有管理员明确触发的离线灾难恢复才允许恢复完整 Xray 快照。
- Reality 隧道路由、套餐/中转用户路由和批量授权改为 Xray RoutingService 运行时替换；热更新失败会回滚已预留的客户端和数据库状态，不会靠重启掩盖失败。
- Agent `v0.4.10` 增加路由热更新及停止状态下的延迟落盘能力：Xray 已停止时只写入配置，不会被后台任务偷偷拉起。
- 转发入站增加完整配置、代际和租约校验，避免过期或被篡改的转发规则继续留在 Xray 中。
- 关闭会绕过数据库权威规则的旧入口，包括入站反向同步、接受 Agent 状态、配置片段写入以及通过原始 Xray 配置增删入站。

### 影响与兼容性
- 升级后，服务器 Xray 中没有对应数据库节点的手工入站会被移除。如需由 Arcway 管理，请先在“节点管理”中创建对应服务器节点；仅导入节点不会在服务器上创建入站。
- 已经由数据库节点管理的 VLESS、WireGuard 和转发入站会自动迁移，不需要重新创建；迁移与日常对账均使用热更新，不会因本次规则调整主动重启 Xray。
- 远程服务器需要升级到 Agent `v0.4.10` 才能使用新的路由热更新协议；可在服务器“Agent 管理”中由管理员逐台确认升级，面板不会自动替换用户管理的 Xray 内核。
- 原始 Xray 配置仍可维护出站、路由及其他非入站设置，但不能再绕过节点管理直接修改入站。
- Docker 部署仍需在宿主机执行镜像更新，不能在容器内执行面板原地更新。

## 更新版本
- 裸机 / systemd：在面板“系统设置 -> 系统更新”检查并更新到 `v0.6.13`。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`。

## 操作方法
1. 更新前完成可恢复的加密备份，并确认服务器可以访问 GitHub Release 下载域名。
2. 检查“节点管理”中的服务器节点是否完整；仍需保留的服务器代理应在这里有对应记录。
3. 裸机 / systemd 部署在面板执行完整更新，等待事务、后端健康检查和网页版本检查全部完成。
4. 更新后打开“节点管理”核对节点，并确认服务器 Xray 中不再保留无数据库归属的旧入站。
5. Docker 部署在宿主机拉取并重建镜像，不要在容器内点击原地更新。
