# 更新日志

## v0.6.9 (2026-08-03)

### 本次更新
- 后端现在内置并校验 Mihomo、Ookla Speedtest CLI 与家用测速端的目标版本、官方下载地址和校验值，不再在运行时盲目追随上游的 latest 标签。
- 已由 Arcway 管理的 Mihomo 与已明确接受 Ookla 许可的 Speedtest CLI 会在控制端启动时检查，之后每 6 小时再次核对；只更新面板管理的副本，绝不覆盖 `MIHOMO_BIN`、`PATH` 或人工安装的程序。
- 家用测速端的 Linux 和 Windows 安装命令只从 GitHub Release 下载，并先校验同一 Release 的 `checksums.txt`；面板不再提供测速端二进制或下载接口。
- 新版家用测速端会在与控制端建立配对连接后接收版本通知，从对应 GitHub Release 校验下载包并自动完成后续更新。
- 系统更新页和测速组件状态统一展示后端批准的目标版本，避免把外部核心版本误认为面板自身版本。

### 影响与兼容性
- `v0.6.8` 及更早安装的家用测速端不含自更新能力。控制端更新到本版本后，需要在“测速端管理”中重新生成配对安装命令并手动安装一次；完成这一次迁移后，后续版本会自动更新。
- 受管节点 Agent、节点配置、数据库、订阅数据及外部 Xray 安装方式不受影响。Agent 仍只从对应 GitHub Release 获取并校验。
- 未由 Arcway 管理的 Mihomo 或 Ookla Speedtest CLI 不会被自动安装、替换或删除；仍可由管理员自行控制。
- Docker 部署仍应在宿主机拉取并重建镜像，不能在容器内执行面板原地更新。

## 更新版本
- 裸机 / systemd：在面板“系统设置 -> 系统更新”检查并更新到 `v0.6.9`。
- Docker：在宿主机执行 `docker compose pull && docker compose up -d`。
- 家用测速端：控制端升级完成后，在“测速端管理”重新配对并执行页面生成的 GitHub 安装命令一次。

## 操作方法
1. 更新前完成可恢复的加密备份，并确认服务器可以访问 GitHub Release 下载域名。
2. 裸机 / systemd 部署在面板执行完整更新，等待事务、后端健康检查和网页版本检查全部完成。
3. 对旧版家用测速端重新执行一次页面生成的安装命令；Linux 与 Windows 安装器都会在替换前验证 SHA-256。
4. Docker 部署在宿主机拉取并重建镜像，不要在容器内点击原地更新。

- 已完成 Linux、Windows AMD64 和 Windows ARM64 家用测速端构建校验。
