# GitHub Release Notes

每个稳定的 RelayDock 标签都必须有一份可读的中文说明，路径为
`docs/release-notes/vX.Y.Z.md`。GitHub 会将该文件原样发布为 Release 正文，
让运维人员在打开面板更新前就能知道本次改了什么。

运行 `scripts/release.sh` 前，从 [TEMPLATE.md](TEMPLATE.md) 创建下一个版本的
说明。发布脚本会在修改版本、创建标签或推送前确认该文件已提交且内容完整；GitHub
工作流会在构建和发布前再次校验。

以下章节必须具体、面向使用者：

- `本次更新`：新增、修复和行为变化。
- `影响与兼容性`：更新范围、迁移要求或明确未受影响的路径。
- `更新版本` 与 `操作方法`：适用时分别说明 standalone/systemd 和 Docker 路径。
- `验证`：只记录发布前已完成的验证，不能把后续工作写成既成事实。
- `完整变更`：上一稳定标签到当前标签的 GitHub 比较链接。

已发布的说明是 Release 记录的一部分，不直接重写；若内容需要修正，应发布新版本。
